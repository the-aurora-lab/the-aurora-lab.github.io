Every Comment Answered: Each Reviewer Point Matched to Your Changes

For papers coming back from review: the decision letter split into numbered comments, every change in your LaTeX or Word manuscript with its page and line, each comment linked to the changes that answer it, and a check before you resubmit that every comment has a reply and every promised change is really in the paper. Your replies stay your own.

  • Python 3.9+, standard library only

What it does

  1. Splits the decision letter into numbered comments. E.1 for the editor, R1.3 for reviewer 1's third point, each quoted exactly. It reads the layouts journals send: Editorial Manager and ScholarOne letters, PLOS questionnaires, eLife reviews, SciPost reports, Copernicus comments, F1000Research reports, OJS, with numbered, lettered, bulleted, line-referenced and section-referenced points.
  2. Finds every change between the version you submitted and the revised one: LaTeX from a git tag, a folder or an Overleaf zip (following \input and \include), or Word, from a file with tracked changes or two files. Each change knows its place: section, figure, table, equation, and the page and line of the revised PDF.
  3. Links each comment to the changes that answer it. It ranks the likely changes for every comment; you, or Claude Code with the included skill, confirm each link after reading it.
  4. Writes the response scaffold in Markdown, LaTeX or Word: every comment quoted, room for your reply, and the changes listed with their places, kept up to date as you keep editing.
  5. Checks before you resubmit that every comment has a reply, that every change a reply promises is linked to a real change, that text a reply quotes is in the paper, that numbers a reply gives are in the paper, and that the section, figure or page a reply names is where the change is. It also lists changes no comment explains.

It never writes your replies. JAMA's 2026 guidance lists author responses to reviewer and editor comments as not an acceptable use of AI, and other journals ask authors to disclose AI-written text; Springer Nature lists structuring reviewer comments as a permitted use. Every Comment Answered stays on the tracking side of that line.

A revision, start to finish

A short paper made up for this demonstration (bicycle-mounted temperature sensors and urban heat), its submitted and revised LaTeX versions with line numbers, and a decision letter from an editor and two reviewers. The authors' replies were written into the scaffold with three mistakes planted for the check to find.

Claude Code links the comments

Then one unattended Claude Code session (Claude Sonnet 5.5) with the skill installed got the request an author would type: link each comment to the changes that answer it, refresh the response, check it and say what is missing. It took 27 seconds and cost $0.10. Its answer, word for word:

The response is refreshed and checked, and it isn't ready to resubmit. I didn't change your replies or the paper.

The letter splits into 9 comments: 1 from the editor, 3 from Reviewer 1 and 3 from Reviewer 2, plus an opening summary for each reviewer.

Answered by a change

  • E.1: C1 adds "from June to August 2025" to the abstract (page 1, line 6).
  • R1.1: C4 describes the three-day side-by-side comparison of the twelve sensors, agreeing within 0.2 degrees (Section 2.1, page 1, lines 17-19).
  • R1.2: C5 removes readings taken while a bicycle stood still for more than a minute (Section 2.2, page 1, lines 21-23).
  • R1.3: C6 changes the Figure 1 caption to say the routes are in grey (page 2).
  • R1.0 and R2.0: these are praise, so I marked them as needing no change.

Partly answered

  • R2.1: C7 is a single sentence in the Discussion (page 2, lines 30-31). It says one summer in one city can't show how the pattern changes and that a second season is planned. The reviewer asked you to "discuss how general the result is", so this may be thin.
  • R2.2: C3 gives an advantage of bicycles: they move slowly enough for a shielded sensor to follow air temperature (Section 1, page 1, lines 12-13). It never compares them with cars.

Problems the check found

  • R2.3, uncertainty of the 1.4 degree difference: your reply says you added "the 95% confidence interval of the difference (1.4 +/- 0.3 degrees) to the Results". The revised paper has no such text. The only change near that number, C2, adds "1.4 degrees … at midday" to the abstract, with no interval. Either the interval never made it into revised/paper.tex, or the reply is ahead of the manuscript.
  • R2.2 has no reply. The Reply field is empty.
  • R1.3 reply: you quote "the routes of all twelve bicycles in grey" as new text. The manuscript only has ", with the twelve bicycles' routes in grey" in the caption. Reword the quote, or check the wording.
  • Figure 1 (not yet checked): your reply says you redrew it. A caption edit is the only change I can see, so I haven't confirmed the figure itself shows the routes.
  • C2 matches no comment. It adds "1.4 degrees … at midday" to the abstract, which no reviewer asked for. It's harmless, but the response doesn't mention it.

revision/check.md and revision/report.html have the details. After you fix these, run every-comment diff, then every-comment scaffold, then every-comment check again.

How well it works

Measured once, on 13 real revisions the tool was never tuned on: 9 SciPost papers (LaTeX from arXiv; astronomy, mathematical physics, particle physics, condensed matter, cosmology) and 4 F1000Research papers (Word, with the tracked changes made by Microsoft Word's own Compare; pharmacognosy, biochemistry, clinical pharmacy, bioinformatics). The reviewers' reports, the authors' real replies and both versions of each paper are public (CC BY). An independent agent, which never ran the tool or read its code, labelled 278 reviewer points: where each point is, what the authors replied, and phrases of the revised text that show each change. In a copy of each paper it then took out again the changes that answer 37 points whose replies still promise them. One Claude Code session per paper (Sonnet 5.5, a median of 55 seconds, $3.30 for all 13) got the request a user would type, then every-comment check ran.

"Points with their own comment" is the cleaner measure of the check: when the split puts several points in one comment, the authors' replies to all of them sit together, and a flag earned by one is charged to all. The seven points the authors left without any reply were all flagged as such; those flags are right and not counted above.

  • Every miss among the missing changes (9 of 22) was a reply the check did not read as a promise: terse ones such as "Addressed", "→ fixed", "Removed from paper.", "Stated that explicitly", and "we propose to change …". Version 1.0.1 reads these too; that has not been re-measured, and the next held-out set will.
  • Splitting finds the points but often keeps neighbours together: reports written as paragraphs that hold several requests (most F1000Research reports) gave 21 of 65 points a comment of their own, SciPost 144 of 213. Read comments.md once and split by hand where needed.
  • False alarms (23): the agent's own "only partly answered" notes on links the labels count as answers; promises about software or figures, which the tool cannot see; quotes of a paper's title or of text with math; numbers and places a reply names.
  • Links to changes the labels do not name are not judged: the labels give one to three phrases per point, not every change. Page and line numbers were not part of this test (the held-out sources were not compiled); the test suite checks them against compiled PDFs.

The guide in the download carries the same results.

What it reads

InputAccepted
Decision letterText, Markdown, a saved email (.eml), HTML, Word, or PDF (with pdftotext)
LaTeX manuscriptThe current folder against a git tag or commit, another folder, a .tex file or an Overleaf zip; \input, \include, \subfile and \import followed; the .aux file's numbers and pages used when present
Word manuscriptOne .docx with tracked changes (insertions, deletions, moves; Word's author and date kept), or two .docx files without them
Page and line numbersFrom the revised PDF built with SyncTeX (pdflatex -synctex=1, latexmk's default), with \usepackage{{lineno}} for line numbers; Word gives the page as it last laid the file out
ResponseMarkdown, LaTeX or Word; your replies are kept every time it is refreshed

You can tag a change yourself, % R1.3 beside it in LaTeX or a Word comment saying R1.3, and it is suggested first for that comment.

Get it and start

Coming to Gumroad and Polar at $19, once: a zip with the Python wheel (the every-comment command and the Claude Code skill), a quickstart and the full guide. Updates for 12 months. Personal-use licence; no licence key.

pip install every_comment_answered-1.0.1-py3-none-any.whl
cd my-paper
every-comment start decision-letter.pdf --old submitted     # a git tag, a folder or an Overleaf zip
every-comment setup skill                                    # then ask Claude Code to "help me answer the reviewers"
every-comment check                                          # before resubmitting

Python 3.9 or newer, nothing else installed with it. Works without Claude Code: every-comment changes --near R1.3 and every-comment link R1.3 C12 do the linking by hand.

What it sends where

  • Nothing. The command reads your letter and your manuscript and writes a revision/ folder beside them; it makes no network requests and has no telemetry.
  • With Claude Code, the skill runs the same commands on your computer. Claude Code sends what the agent reads to Anthropic as it always does; the tool adds nothing to that.

Limits

  • LaTeX and Word only; a manuscript that exists only as a PDF cannot be compared.
  • Splitting follows the letter's layout; a letter written as unbroken prose splits by paragraph. Read comments.md once and merge or split what needs it.
  • Suggestions come from shared words, quoted phrases, the places a comment names and your tags. A person or the agent confirms each link; a wrong link hides a missing change from the check.
  • The check recognises the usual ways of saying the manuscript changed; a promise in unusual words may pass.
  • Figure images and software are not compared: a redrawn figure shows only through its caption.
  • Tested on macOS with Python 3.9 and 3.14, TeX Live 2026, Microsoft Word for Mac and Claude Code 2.1.319. Windows is untested.
